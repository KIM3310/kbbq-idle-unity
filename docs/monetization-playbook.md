# Monetization Playbook - kbbq-idle-unity

This file is a commercial planning artifact, not a guarantee of revenue. Use it to make the repository legible as a sellable product, pilot, workshop, license, or proof-of-value package.

## Commercial Lane

- **Lane:** B2C game and ad monetization
- **Primary buyer:** Casual game publishers, ad-supported mini-game operators, and playable portfolio reviewers.
- **Revenue wedge:** Playable K-BBQ idle loop with WebGL hosting and ad-review path.

## Offer Ladder

1. **Ad-supported WebGL game** - pricing hypothesis: Ads/IAP experiments
2. **Publisher prototype** - pricing hypothesis: $500-$3k publisher prototype
3. **Playable portfolio/game-jam asset** - pricing hypothesis: $2k-$8k playable polish contract

## Acquisition Channels

- Itch/WebGL demos
- Short gameplay clips
- Publisher outreach with retention metrics

## Proof Gates Before Selling

- Unity play loop works
- WebGL docs path is clear
- Backend tests pass if backend is used

## Risk Boundaries

- No copied assets
- Ad compliance required
- Retention must be measured before scaling

## 30/60/90 Day GTM

- **30 days:** Add 5-minute session analytics
- **60 days:** Test ad slot UX
- **90 days:** Publish one WebGL build

## Metrics That Matter

- Session length
- Upgrade loop conversion
- Ad RPM readiness

## Positioning Note

Lead with the specific operational pain, then show the runnable proof, then offer a narrow pilot. Do not pitch the repository as a vague app; pitch it as a concrete workflow with evidence, risk boundaries, and a next buying step.
